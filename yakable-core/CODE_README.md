# yakable-core 编程规范

本规范适用于 `yakable-core` 下所有 Java 代码，只约束通用编码风格，不包含具体业务规则。

## 代码格式

1. 简单方法声明、构造方法、record 声明和方法调用能一行写完就写一行。

2. 只有参数较多或单行明显过长时才允许换行，禁止为了一个参数做无意义换行。

3. 换行后保持结构紧凑、统一。同一组参数、同一段链式调用使用一致的缩进方式。

4. 禁止把 `) {` 单独悬空。多行方法声明的最后一个参数应与右括号、左花括号保持在同一行。

5. 方法调用同样遵循紧凑原则，禁止把右括号单独拆成一行。

6. 链式调用只有在单行明显过长时才换行，换行后每一级调用保持同一缩进层级。

7. 禁止为了“看起来整齐”增加没有必要的空行、换行和缩进层级。

## 代码结构

8. 一个类只承担明确职责，能在当前类内清晰表达的逻辑不要提前拆成新的 Manager、Helper、Handler、Adapter 等中间层。

9. 没有真实复用场景时，不为了减少少量重复代码提前抽象公共类或公共接口。

10. 私有实现细节优先使用 `private` 方法收敛，只有形成稳定公共能力后再向外抽取。

11. 命名直接表达职责和语义，禁止使用含义模糊的 `Utils`、`Manager`、`Processor` 等名称承载具体业务逻辑。

12. 能直接返回表达的结果不增加无意义的临时变量；能直接调用已有能力不增加一层无意义转发。

## 基本原则

**保持简单、紧凑、统一。**

**没有真实问题之前，不提前增加抽象。**
